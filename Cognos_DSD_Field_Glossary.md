# Cognos NH MMIS Report Definition (DSD) — Field Glossary

A plain-English reference for every field on the standard NH MMIS Report
Definition (DSD) template, based on the annotated walkthrough of
**PRV-INT-027 — Provider License Interface – Term Date Report**. Field
names and layout match the template exactly, so this glossary applies to
any report built on the same DSD form, not just PRV-INT-027.

---

## 1. Report Definition (header block)

| Field | Meaning |
|---|---|
| **Report Type** | Standard / Customized — the DSD template category being used. |
| **Client Name** | The state/client the report is built for (e.g. New Hampshire). |
| **Client Report ID** | The unique report identifier (e.g. `PRV-INT-027`). |
| **Client Line of Business** | The program area the report belongs to (e.g. Medicaid). |
| **Client Division/Department** | The owning department (e.g. DHHS). |
| **Report Title** | The formal, human-readable name of the report. |
| **Report Description** | What the report records or is used for. |
| **Report Source Type** | Whether the report's data comes from OLTP or OLAP. |
| **Report Source Type Component** | Which functional module the report belongs to — e.g. Provider, Member, Operations, Program. This tells you which subsystem "owns" the data. |

---

## 2. Report Generation

| Field | Meaning |
|---|---|
| **Report Generated by** | The generating system/tool (EQR, EFADS, EMAR, ESUR, or Other). |
| **Report Screen Tip (optional)** | Optional hover/help text shown for the report in the portal. |
| **Report Calendar Type** | Whether report timing follows the State Fiscal or Federal Fiscal calendar. |
| **Report Frequency Type** | Controls *how* the report runs: if **Scheduled** is checked, the report runs automatically via IWA (the scheduler). If **On Request** is checked, someone has to manually generate the report — it does not run on its own. |
| **If Scheduled, select timeframe below** | The cadence the scheduler uses when Frequency Type = Scheduled: Daily, Weekly, Monthly, Quarterly, or Annually — i.e., what time interval triggers the report run. |
| **Other – Please explain** | Free text used when the schedule/trigger doesn't fit the standard options — e.g. this report is instead triggered by errors from a specific upstream job. |
| **Report Data Accumulation Type** | Whether the report accumulates data Daily, Weekly, Monthly, Quarterly, Annually, or Year-to-Date (YTD). |
| **Triggered by...** (free text under Frequency) | Describes *what upstream process kicks off this report* — e.g. "any errors from the most recent execution of the daily interface job." In other words: is this report driven by an Informatica ETL job or a "core" (application) job finishing? |

---

## 3. Report Selection Criteria & Parameters

| Field | Meaning |
|---|---|
| **Report Selection Criteria** | The filter conditions applied to the report — e.g. "report begin date > current date." This is where business-level filtering rules are defined in plain language. |
| **Report Field** (under Selection Criteria) | The actual column the filter condition runs against — e.g. `Where P_RPT_CLDI_TERM_TB.P_CMN_LIC_CERT_END_DT >= P_RPT_CLDI_TERM_TB.G_RPT_PRCS_DT`. This ties the business filter description to a real source-table.column. |
| **Report Parameters (optional)** | Optional runtime parameters a user can supply when running the report. |
| **Note: If populated, Prompt must = No** | If a parameter has a default/fixed value populated here, then it can't also be an interactive Cognos prompt (Prompt = No). The parameter row shows which column/label the parameter maps to — e.g. the same `P_RPT_CLDI_TERM_TB.P_CMN_LIC_CERT_END_DT >= ...G_RPT_PRCS_DT` reference. |
| **Prompt** | Whether Cognos should show an interactive prompt to the user for this parameter (Yes/No). |

---

## 4. Report Control Breaks, Totals, Counts, and Sort

| Field | Meaning |
|---|---|
| **Sort By** | How the report rows are ordered — based on a business label (column name), Ascending or Descending. |
| **Control Break** | Where the report inserts a break/grouping boundary, keyed off a business label. Breaks can happen at the **Page** level or the **Section** level (e.g. a control break on Section vs. a control break on Page). |
| **Total** | A sum/aggregate shown at a break point — computed **Grand** total (whole report) vs. **Section** total (per group), at page end or section end. |
| **Counts** | A record count shown at a break point — same Grand vs. Section distinction as Total, i.e. how many records fall in that page/section. |

---

## 5. Report Output

| Field | Meaning |
|---|---|
| **Report Output Format** | The file format Cognos generates the report in — PDF, HTML, Excel 2000/2002, or Text/CSV. |
| **Reporting Portal** | Where the finished report output is delivered/stored — Web Portal, EDMS, or emailed as a link. |
| **Report Output Distribution Group(s)** | Whether the report also goes to a distribution group list, and if so, who's on it. |

---

## 6. Report Retention

| Field | Meaning |
|---|---|
| **Report Retention Type** | Where the report output is stored long-term — Cognos or EDMS. |
| **Report Output Versions** | How many historical copies (occurrences/duration in days, months, or years) are kept in the EDMS. |
| **Report Run History Log** | How long the run-history log itself is retained (occurrences/duration). |

---

## 7. Report Layout

The layout section shows how the finished report actually looks on the
page. Everything under **Enterprise Operational Reports (EOR)** is
standard boilerplate shared by every DSD; only a few fields change per
report:

| Field | Meaning |
|---|---|
| **Enterprise Operational Reports (EOR)** header block | Identical structure across every DSD in this template family. |
| **Report ID** | Changes per report — the same Client Report ID from Section 1 (e.g. `PRV-INT-027`). |
| **File Name** | Changes per report — the actual output filename pattern for this report. |
| **"Department of Health and Human Services"** | The fixed page header text. |
| **Report title line** (e.g. "Provider License Interface – Term Date Report") | The report's title as it appears on the printed/rendered page. |
| **NH State logo** (right side) | Fixed branding element on every report. |
| **Report section & label names** | The column/section headers that appear in the body of the rendered report. |
| **Footer** | Identical across every report in this template family (Run Date, Page, Run Time, etc.). |

---

## 8. Report Specification

| Field | Meaning |
|---|---|
| **Presentation Type** | The Cognos object type used to render the report — List Object, Crosstab Object, or Repeater Object. Most reports in this template family use **List Object**. |
| **Report Section Heading (opt)** | The report's layout header content — typically File Name, the run date (`MM/DD/CCYY`), and a total, shown together at the top of the section. |
| **Business Label / Field Description / Source Table / Source Column / Source Column Processing Rules** | The core field-mapping block. **Business Label** (from the Report Body) and the label shown in the Report Layout must match — they're the same name viewed from two different parts of the template. Each row then ties that business-facing label back to its **Field Description** (what it means), **Source Table** and **Source Column** (where the data physically comes from), and any **Source Column Processing Rules** (formatting/derivation logic, e.g. `Format MM/DD/YYYY`). |
| **Chart Header / Chart Footer / Report Footnote (opt)** | Optional chart-specific and footnote sections — left blank (N/A) when the report doesn't use them, as in a plain list report. |

---

## Quick cross-reference: how the sections connect

1. **Report Definition** names the report and states *why* it exists.
2. **Report Generation** decides *when/how* it runs (scheduled vs. on-request, and what triggers it).
3. **Report Selection Criteria & Parameters** decide *which rows* qualify, both in business terms and as an actual `table.column` filter.
4. **Control Breaks / Totals / Counts / Sort** decide *how the rows are grouped and ordered* once selected.
5. **Report Output & Retention** decide *what format the result comes in* and *how long it's kept*.
6. **Report Layout** shows what the *rendered page* looks like.
7. **Report Specification** is the definitive field-mapping table connecting every **Business Label** shown on the page back to its real **Source Table.Source Column**, which is what a tester ultimately needs to verify the report is pulling correct data.
